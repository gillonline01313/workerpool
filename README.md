# WorkerPool

Website for **workerpool.ca**: free candidate profiles for temporary residents in Canada and foreign workers abroad, plus employer and licensed-partner interest. Hosted on Cloudflare Pages with Pages Functions and a D1 database. No paid analytics or third-party trackers.

## Deploy on Cloudflare (one time)

1. **Create the database.** Cloudflare dashboard → Storage & Databases → D1 → Create → name it `workerpool-db`. Open it → Console → paste all of `schema.sql` → Execute.
2. **Create the site.** Workers & Pages → Create → Pages → Connect to Git → choose `gillonline01313/workerpool`.
   - Framework preset: None. Build command: leave empty. Build output directory: `/`.
   - Save and Deploy.
3. **Connect the database.** Your Pages project → Settings → Bindings → Add → D1 database → Variable name `DB` → database `workerpool-db`. Save.
4. **Set the admin key.** Settings → Variables and Secrets → Add → Type: Secret → Name `ADMIN_KEY` → a long random password only you know. Save.
5. **Redeploy** so steps 3 and 4 take effect: Deployments → latest → Retry deployment.
6. **Add the domain.** Custom domains → Set up a custom domain → `workerpool.ca` (and `www.workerpool.ca`).

Then open `https://workerpool.ca/admin/` and enter your admin key.

## Client intake forms (admin → Intake forms)

Pick an application type under **Temporary residence applications** (Outside Canada / Inside Canada) or **Permanent residence applications**. Types marked *Soon* aren't built yet; **Visitor visa (TRV), outside Canada** is ready. Picking a ready type highlights its client link: **Copy link**, send it on WhatsApp, or **Preview** it. Open *Make a personal link for one client* to create a link with the client's name (and optionally email it to them); the table shows when each personal link was opened and how many forms were started and submitted. **Turn off** stops a personal link working.

The client opens the link, creates a WorkerPool account (or signs in), fills the form and uploads documents. Questions and the document checklist change with their answers (married → marriage certificate, host in Canada → invitation letter and host's status, employed → job letter and pay slips, under 18 → birth certificate and consent letter, and so on). Submit stays locked until every required answer and document is in. One account can fill forms for several family members.

Under **Client forms**, submitted forms show highlighted as **New** (or **Updated** after a resubmission) until you open them, and the tab shows the count. Open one to see every answer by section, the documents grouped by checklist item (View / Download / **Download all files**), anything still missing, and the account's contact details. Set a work status and private notes, **Print / save PDF**, **Copy answers**, **Let client edit and resubmit**, or delete the form and its files permanently. `ADMIN_EMAIL` gets an email for each submission and resubmission; the client gets a confirmation.

**Consent, the complete file and destroying documents.** Before Submit, the client must tick an explicit consent: WorkerPool uses the information only to prepare the application, the team permanently destroys every uploaded document once the file is complete, and the complete submitted file is shared with the client for future reference. They must also choose, separately, whether WorkerPool should **save the complete file** for future reference (kept in their account until they ask to remove it) or not (removed 30 days after it's shared). The exact wording and time are stored with each submission, asked again on every resubmission, and the client can change the save choice later. In the admin form view, **Create & share complete file with client** builds one ZIP (an answers summary PDF plus every document in numbered folders, up to 95 MB), puts it in the client's account and emails them; then **Destroy uploaded documents** deletes every upload permanently and emails the client. Files the client chose not to save are removed automatically after 30 days. A form can't be reopened once its documents are destroyed. Consent wording: `CONSENT_TEXT` and `KEEP_TEXT` in `assets/intake-config.js` (bump `CONSENT_V` when you change it); the file builder is `functions/_intake_file.js`.

The TRV form follows IRCC's Application for Visitor Visa (IMM 5257), Schedule 1 (IMM 5257B), the Family Information form (IMM 5707 / IMM 5645) and the online visitor visa document checklist. Tables (`intakes`, `intake_docs`, `intake_invites`) are created automatically; files go to the private `RESUMES` R2 bucket under `intake/`. When you change `assets/intake-config.js` or `admin/intake.js`, bump the `?v=` on their imports (`intake/index.html`, `admin/index.html`, `admin/intake.js`).

## Partner intake forms for RCICs and law firms (/partners/)

Licensed representatives (RCICs, lawyers, Ontario paralegals, Quebec notaries, or firms employing them) create their own account at `/partners/` with their firm name, licence number and contact details, and accept the partner terms. **Every new firm needs your approval.** The firm can sign in but only sees "Waiting for approval" until you approve it: no credits, no payments, no links. `ADMIN_EMAIL` gets an "Approve new intake partner" email for each application, and admin → **Partners** shows the count on the tab with the firm marked *Needs approval* (check RCIC licences on the CICC public register at college-ic.ca, lawyers on their law society's directory). Open the firm and press **Approve firm** (they're emailed and can start) or **Decline** (optional reason, emailed to them; they can't sign in). Pause an approved firm any time.

**Pricing.** $10 CAD per Temporary residence intake form and $20 CAD per Permanent residence intake form (change both in admin → Partners → Save prices; new purchases use the new price). Firms buy credits with Stripe Checkout (same `STRIPE_SECRET_KEY` as the Profile Scanner; `STRIPE_TAX` = `on` adds GST/HST). No webhook: the payment is confirmed with Stripe when the firm returns, and each Stripe session adds credits exactly once. Without Stripe, add credits by hand in admin → Partners (also use this for e-Transfer payments or free trials; use a minus number to remove). Permanent residence credits can't be bought until a Permanent residence form is built.

**Links.** Each personal client link uses one credit of its kind and opens **one** form for **one** client account (a second person using the same link is refused). Turning a link off before the client starts the form returns the credit. Clients see the firm's name on the form; their consent names the firm (`partnerConsent` in `assets/intake-config.js`) and there's no "keep a copy with WorkerPool" choice. On submit the firm, `ADMIN_EMAIL` and the client are emailed.

**What the firm can do** (only with its own clients' forms, and only once submitted): view every answer and document, download each file or one ZIP (answers summary PDF plus every document in numbered folders, built on the spot), print/save PDF, copy answers, set its own work status and private notes, reopen the form for the client with a message, and, after downloading the ZIP, delete the uploaded documents from WorkerPool (the client is emailed).

**Master view.** Admin → **Intake forms** shows every partner form (filter **Partner firms**) with the firm's name, licence and status, including forms still being filled. Admin can view and download everything (**Download complete ZIP**), unlock, delete documents or delete the form. Admin → **Partners** lists each firm with credits, links, forms, payments and the full credit history.

Tables (`partners`, `partner_sessions`, `partner_resets`, `partner_ledger`, `partner_payments`, `partner_settings`, plus partner columns on `intakes` and `intake_invites`) are created automatically. Partner sign-in uses its own cookie (`wp_p`), separate from client accounts.

## Live chat

Run `schema-chat.sql` in the D1 console once. Replies happen in the admin dashboard under **Live chat** (it checks for new messages every 5 seconds while open, and shows an unread count on the tab and in the browser tab title). `ADMIN_EMAIL` gets an email for each new chat, every message sent outside live hours, and after 10 quiet minutes on an ongoing chat. If a visitor has left the page when you reply and they gave an email, your reply is emailed to them too. Both sides can share files (PDF, JPG, PNG, DOC, DOCX up to 10 MB; visitors up to 25 per chat), stored privately in the `RESUMES` R2 bucket under `chat/`. Visitors can only open files in their own conversation. Visitors can also leave a **voice note** (up to 2 minutes) from the mic button beside the chat button or inside the chat; it joins their conversation, emails `ADMIN_EMAIL` every time, and plays in the Live chat tab (with a download link). Same hours as chat: outside 8:00 to 23:00 an email is required. Recordings are stored in the same R2 bucket under `chat/` (`functions/api/chat-voice.js`). The site's `_headers` allow the microphone on workerpool.ca only. When you change `assets/chat.js`, bump the `?v=` number on its script tags (home, `/news/`, `/express-entry-2026/`). To change the hours, edit `CHAT_OPEN`/`CHAT_CLOSE` in `functions/_lib.js` and `OPEN`/`CLOSE` in `assets/chat.js`.

## Profile Scanner

Needs a Workers AI binding: Pages project → Settings → Bindings → Add → **Workers AI** → Variable name `AI`. Save, then redeploy. Workers AI bills per use; one scan of 6 documents costs well under a cent, and the first 10,000 "neurons" a day are free.

**Payments ($9.99 CAD Scanner Pass: 30 days, up to 25 document reads, unlimited rescans).** The scanner only reads documents for visitors with a pass; the free example stays open to everyone.

1. Stripe dashboard → Developers → API keys → copy the **Secret key** (`sk_live_…`; use `sk_test_…` first to try it with Stripe's test card 4242 4242 4242 4242).
2. Pages project → Settings → Variables and Secrets → Add → Type **Secret** → Name `STRIPE_SECRET_KEY` → paste the key. Save and redeploy.
3. Optional: `STRIPE_TAX` = `on` to have Stripe Tax add GST/HST at checkout (turn on Stripe Tax and add your GST number in Stripe first).
4. Optional: `SCANNER_FREE` = `on` opens the scanner to everyone without a pass.

No webhook is needed: `functions/api/scanner/[[path]].js` confirms each payment with Stripe when the buyer returns. Buyers who lose access press **Already paid?** and get their link by email (needs `RESEND_API_KEY`). Promotion codes you create in Stripe work at checkout. The admin dashboard's **Scanner passes** tab shows sales, revenue and documents read, and **+ Free pass** creates a link that unlocks the scanner for a client. Passes live in the `scan_passes` table (created automatically): an ID, dates, amount and a document counter only. **Price and coupons:** admin dashboard → **Scanner passes**. **Change price** sets the website price (minimum $0.50; stored in the `scan_settings` table). **+ New coupon** creates a code with any discount from 1% to 100%, an optional use limit, expiry date and note; each coupon has a **Copy link** that opens the scanner with the discount applied (`/tools/profile-scanner/?coupon=CODE`). Coupons can be edited, paused, resumed or deleted, and a use is counted when its payment is confirmed (a 100% coupon unlocks without Stripe). Coupons and the admin price apply to website checkout only; the Android app's price is set in Google Play Console. The pass length and document limit are in `functions/_scanpass.js` (`PASS`).

## Android app (Google Play)

`android/` is a Trusted Web Activity: the app opens https://workerpool.ca full screen (package `ca.workerpool.app`), so every website change appears in the app straight away. GitHub Actions (`.github/workflows/android.yml`) builds it whenever `android/` changes, or on demand from the Actions tab → Android app → Run workflow.

- **Signing.** `android/upload-keystore.p12` is the upload key (alias `upload`). Add its password as the GitHub repository secret `ANDROID_KEYSTORE_PASSWORD` (Settings → Secrets and variables → Actions). With the secret set, each build publishes a GitHub release with the signed `.aab` (upload this to Play Console) and `.apk`. Keep a copy of the password and the key file somewhere safe; Google Play needs the same upload key for every update.
- **App links.** `/.well-known/assetlinks.json` (`functions/.well-known/assetlinks.json.js`) lists the upload key. After the first upload, copy Play Console → Test and release → App integrity → App signing key certificate → SHA-256 fingerprint into the Cloudflare variable `ANDROID_CERT_SHA256`. Without it, the app shows a browser address bar.
- **Google Play Billing.** Inside the app the Profile Scanner is sold through Google Play (in-app product `scanner_pass`, a one-time consumable) instead of Stripe. `POST /api/scanner/play` checks each purchase with the Google Play Developer API, issues the pass and consumes the purchase. It needs the Cloudflare secret `GOOGLE_PLAY_SERVICE_ACCOUNT` (the JSON key of a Google Cloud service account with the Google Play Android Developer API enabled, invited in Play Console → Users and permissions with "View financial data" and "Manage orders and subscriptions").
- **Store listing assets:** `android/store/icon-512.png` and `android/store/feature-graphic.png`. Account deletion link for the Data safety form: https://workerpool.ca/privacy/#delete-account

## Flight Deal Finder (/tools/flights/)

Finds the cheapest way to fly between two cities: regular tickets, self-transfer routes through up to 10 hub airports (`HUBS` in `functions/_flights.js`), cheaper days within 3 days, nearby airports, and two one-ways instead of a return. Prices come from the Travelpayouts (Aviasales) Data API: fares Aviasales users found in the last 48 hours. Every "Book" link carries your partner marker, so bookings earn commission.

Setup (Cloudflare → Pages → Settings → Variables and secrets):

| Name | Type | What |
|---|---|---|
| `TP_TOKEN` | Secret | Travelpayouts API token (Travelpayouts → Profile → API token). Without it the tool says prices aren't switched on. |
| `TP_MARKER` | Text | Your Travelpayouts partner ID (marker), added to every booking link |
| `TP_MARKET` | Text | Optional. Aviasales market for prices, e.g. `ca` |
| `TELEGRAM_BOT_TOKEN` | Secret | Optional. Token from @BotFather. The webhook registers itself the first time the flight page loads. |

**Alerts** (`functions/api/flights/[[path]].js`, table `flight_alerts`, created automatically): people set an alert for a route and date, with an optional target price, and choose email (needs `RESEND_API_KEY`; the address must be confirmed), Telegram, or a notification on that phone or browser (Web Push, including in the Android app; the push keys are made once and kept in D1, no setup). Without a target, "a very good deal" means 15% under the price when the alert was set, and each later alert needs a further 5% drop. `.github/workflows/flights.yml` runs every 3 hours and calls `POST /api/flights/check` until every due alert is checked; each alert is checked at most every 3 hours, so the endpoint is safe to call by hand. Alerts stop after the travel date. Every alert has a manage link (`/tools/flights/?alert=…`) to stop it; Telegram users can send `/stop`.

## Email to people who signed up (admin → Email)

The **Email** tab in the admin dashboard sends a message to anyone on the site's lists: all accounts, people who submitted (or didn't finish) the questionnaire, people who agreed to updates, forum members, Student Pool, B2B clients and employer interest. Tap a group to pick everyone in it, tick or untick people, write a subject and message (`{name}` becomes each person's first name), **Send me a test**, then send. Up to 4,000 people per send; past sends are listed with sent / failed / skipped counts and **Use again**.

Emails go through Resend (`RESEND_API_KEY`) from `info@workerpool.ca`, and replies come back to that inbox. Because `workerpool.ca` is already verified in Resend for `noreply@`, any address on the domain can send; make sure the SPF, DKIM (and ideally a DMARC `p=none` record) from Resend → Domains are in the DNS, or mail lands in spam. Each email has a plain-text and HTML version, a footer saying why they got it, and an unsubscribe link plus one-click `List-Unsubscribe` headers (required by Gmail and Yahoo). Unsubscribes (`/api/unsubscribe`, signed links) are stored in `email_unsubs` and always skipped; a person can be resubscribed only if they ask. Sends are logged in `email_campaigns`. Both tables are created automatically. Resend's free plan allows 100 emails a day and 3,000 a month; larger sends need a paid plan. Code: `functions/_mail.js`, `functions/api/unsubscribe.js`, admin routes `mail*`.

**Templates and personal emails.** The Email tab has 15 ready-made templates (welcome, unfinished profile, profile reviewed, missing details, missed call, Employer Match, licensed-consultant hand-off, Student Pool, B2B, employer interest, forum, check-in and a gentle "can't help right now"). Pick one, edit it for the person, and send. **Personal** style sends a plain email that reads like it was typed by a person: from "Name from WorkerPool <info@workerpool.ca>", signed with that name, "Care Team, WorkerPool" and the website, with no banner or bulk footer (unsubscribe still works through the email headers). **Newsletter** style keeps the branded layout and footer for group announcements. `{name}` is the person's first name and `{sender}` is the signer's first name. **Save as my template** keeps your own versions in the `email_templates` table. Edit the built-in templates and the care team names in `functions/_templates.js`.

**Sent emails and receipts.** Every email sent from the Email tab (tests included) is kept exactly as the person received it: from, to, reply-to, subject, the HTML version and the plain-text version (`email_sent` table). Under **Sent emails**, search by subject, person, email or signer, and press **View** to open the send: counts of sent / delivered / read / bounced, everyone it went to with their receipt, and each person's email shown as they see it. Opening an email in the admin never counts as a read.

- **Read receipts** work with no setup: each email has an invisible 1×1 image unique to it (`/api/mail-open`). The first open, the latest open and the number of opens are recorded. Reads are an estimate: people who block images aren't counted, and Apple Mail's privacy setting can show a read when the email was only downloaded.
- **Delivery receipts** come from Resend. In Resend → **Webhooks**, add `https://workerpool.ca/api/mail-events` with the events `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained` (and optionally `email.opened`, `email.clicked`), then put its signing secret in Cloudflare as `RESEND_WEBHOOK_SECRET` (`functions/api/mail-events.js`, signature-checked). Bounces show the reason, and anyone who marks an email as spam is unsubscribed automatically. The full history of each email is in `email_events`.

## Latest draws: refreshing by hand

The reader (`scripts/draws/fetch.mjs`, run by `.github/workflows/draws.yml`) checks official pages at 8 am, 2 pm and 8 pm Mountain time. When a source fails (for example a government server timing out), the admin **Latest draws** tab shows it in red with its error:

- **↻ Refresh now** re-reads every source. **↻ Retry failed sources** (or *retry* next to one source, or **↻ Refresh** on the Sources view) re-reads only those; every other source keeps its last result. The tab shows progress and reloads by itself when the site has published the new scores, usually 2–4 minutes later.
- Pages that block automated readers (PEI, NL, Yukon, North Bay, Brandon) can't be refreshed automatically. Their **+ add** / **+ Add draw** buttons open the draw form already filled in with the province, program and official link, so you only type the date, stream, invitations and score.
- From GitHub you can do the same: Actions → Latest draws → Run workflow, with source ids such as `sk,ee` (empty = all).

Needs the `GITHUB_TOKEN` secret above.

## Study options matcher (Student Pool)

Admin → **Study options** holds WorkerPool's own catalog of schools and programs (`functions/_study.js`, tables in `schema-study.sql`, created automatically):

- **Schools**: starts with a list of public colleges, polytechnics and universities across Canada, all unticked. Tick **On ApplyBoard** for each school you can see in your ApplyBoard recruiter account. Only ticked schools are ever suggested.
- **Programs**: add from each college's official program page (level, field, intakes, tuition, IELTS/PTE/TOEFL/Duolingo, minimum marks, gap, PGWP, link), or paste many at once under **Import** (spreadsheet cells or CSV with a header row).
- **🎓 Find options** on a Student Pool profile ranks the programs against the student's highest education, marks (CGPA ×9.5), English scores and bands, study gap, backlogs, budget, intake, level and field. Each option shows ✅ / 🟡 / ⛔ checks. Tick the ones to send, then **Copy email** or **Open in email app**, and **Save to notes & mark “Options sent”**.

Applications are made by hand in ApplyBoard. The tool never logs in to, reads from or copies ApplyBoard (its recruiter terms forbid bots, scraping and sharing its content).
